# video_manager —— 视频库管理工具

用 Python 写的一个视频文件夹管理工具：**建索引、出报表、查重、打标签**。

一条底线始终不变：**它不会删除、移动、重命名任何视频文件**。
扫描和查询只读取被管理文件夹的元数据；写入只发生在自己的索引数据库里
（标签、哈希缓存、索引记录）。视频文件永远只被读，不被改。

## 为什么先做这些

`F:\请输入文本\HSCK` 里是 59 个视频 / 9.49 GB，文件名的信息量很低
（`天美传媒TMY0031…-黄色仓库-hsck.net.mp4` 这类），想整理之前先得看清里面到底有什么。
所以先把「看清」做到位，整理类的破坏性功能留到后面，并且要做成
试运行 + 操作日志 + 可回滚。

### 配色：粉 + 白

**所有颜色集中在 `gui/style.py` 的 `PALETTE` 里**，样式表和卡片绘制
（`card.py`）都从这一份取色 —— 改主题只改一处，不会改不齐。

配色不是把整个界面刷成同一种粉，而是**刻意拉开各区域的深浅**，
否则「整屏一个调子，分不清哪是哪」：

| 区域 | 颜色 | 作用 |
|---|---|---|
| 无边框窗口那圈边框 | `#f9a8d4` 粉-300 | 最深，窗口边界清楚 |
| 顶部标签条 | `#fbcfe8` 粉-200 | 读作标题栏 |
| 中间网格底（画布） | `#fce7f3` 粉-100 | 白卡片从这里跳出来 |
| 卡片 / 侧栏 / 详情面板 | `#ffffff` 纯白 | 内容区，靠粉色画布衬出来 |
| 强调色（选中、勾选、主按钮） | `#ec4899` 粉-500 | 一眼看到「当前状态」 |
| 卡片上的标签 chip | `#be185d` on `#fce7f3` | 和筛选 chip 区分开 |

想换配色（比如改成蓝的），只改 `PALETTE` 里那十几个色值就行。

> **给面板类的 QWidget 子类设样式表背景时，必须打开 `WA_StyledBackground`**，
> 否则 `background` / `border` / `border-radius` 全部不生效 ——
> 普通 `QWidget` 实例不用，只有子类要。这个坑真踩过：
> 详情面板的白底、收起后的粉色圆角块、筛选区那条分隔线，
> 一度全都没画出来（只看到父级的颜色），而且**状态、属性、几何全都正常**，
> 只有抓像素才看得出来。现在有两个像素级回归测试盯着。

### 布局：浏览器式标签页 + 缩略图网格

顶部**没有菜单栏，也没有工具栏，也没有 Windows 自带的标题栏**，
只有标签页和右端的一排按钮：

- `⟳` 扫描 / 更新索引（唯一常驻按钮，因为这是核心动作）
- `⋯` 低频全局操作：选择根目录 / 打开数据库文件夹 / 导出 CSV / 生成 HTML 报表 /
  导入导出标签备份 / 撤销标签操作 / 关于 / 退出
- `─` `□` `✕` 自己画的最小化 / 最大化 / 关闭

**启动即全屏**（占满屏幕可用区域）。想以固定大小启动就改 `vm_config.toml`：

```toml
[gui]
start_maximized = true   # 改成 false 就按下面的比例开窗
window_fraction = 0.5    # 0.7 = 七成，1.0 = 铺满；窗口居中
```

三栏宽度**随窗口大小自适应，并在窗口尺寸变化时重新分配**：

- 小窗时两侧面板按比例收窄（1280 宽时详情面板约 218px，全屏时 330px），
  中间优先保住卡片区；
- 从全屏还原成窗口时会**按新宽度重算**，不会留着全屏时的绝对宽度
  （以前会：1280 的窗口里详情面板硬占 330px，把卡片区挤掉一大块）；
- 你自己拖过分隔条之后，缩放时按你的比例走，不强行套回默认分配；
- 换尺寸档位（全屏 ↔ 窗口）会重新按新宽度分配一次。

**每行显示几个可以随时切换（2 / 3 / 4），卡片和缩略图跟着宽度一起缩放**：

- 顶部 `▦` 按钮，或者按 `Ctrl+2` / `Ctrl+3` / `Ctrl+4`；
- **窗口和全屏各记一份设置**：窗口模式默认 2 个，全屏默认 3 个（铺满屏幕后 3 列最舒服）；
  两边的设置互不干扰，在哪种模式下改的就是哪一份，都存在 `var\gui_state.json` 里；
- 选了几列就**一定是几列**：卡片宽度的算法里不做「好看下限」的钳制，
  否则视口一窄，实际列数会少于你选的数量，而菜单还显示你选的值；
- `▦` 的提示里会带一句自检结果（实际排下几列），万一哪天对不上，一眼就能看出来；
- 缩略图始终保持 16:9，窗口一宽，图就变大（文字区高度不变）；
- 抽帧分辨率按卡片宽度往上取档（360 / 480 / 640 / 800 / 960），
  不会因为拖窗口生成无数种尺寸的缓存；
- 拖窗口时防抖 150ms 再重排，拖的过程中不每帧重算。

![全屏 3 列](var/report/gui_fullscreen.png)

> 想改列数选项或全屏默认值：`gui/main_window.py` 的 `COLUMN_CHOICES` 和
> `AUTO_COLUMNS_WHEN_MAXIMIZED`；格子尺寸的算法在 `gui/grid.py`。

窗口是无边框的，自己实现了拖动、缩放和最大化：

| 操作 | 怎么做 |
|---|---|
| 移动窗口 | 拖标签条的空白处 |
| 最大化 / 还原 | 双击标签条空白处，或点 `□` |
| 缩放 | 拖窗口四边和四角（6px 热区，鼠标会变成相应的箭头） |

**四角是圆的**，而且这个圆角是交给 Windows 11 的 DWM 做的
（`DWMWA_WINDOW_CORNER_PREFERENCE`），不是自己开透明背景画：

- 抗锯齿由 DWM 处理 —— 自己用 `setMask` 只能切出锯齿边；
- 系统**连客户区一起裁**，子控件不会从圆角里"戳"出来；
- 顺带把**系统投影**也带回来了（无边框窗口本来丢掉的就是它）。
- **最大化时自动切回方角**：窗口是贴着屏幕边铺满的，还倒角的话屏幕四角会露出桌面
  （Windows 自己的最大化窗口也是方的）。还原后自动变回圆角。

> 老系统上会安静地退回方角：这个属性是 Windows 11（build 22000）才有的，
> Win10 及更早调用会失败（`apply_corner_preference` 返回 `False`，不报错）。
> 为它去自绘透明窗口不划算 —— 见上面那三条代价。

> **逃生通道**：无边框模式万一拖不动或缩放不顺手，
> 用 `py vm_gui.py --native-frame` 立刻回到 Windows 原生标题栏；
> 也可以在 `vm_config.toml` 里把 `[gui] frameless` 改成 `false`。
>
> 已知代价：无边框模式下**没有 Aero Snap**（拖到屏幕边缘自动分屏）和系统窗口动画。

页面本身是**缩略图网格**（视频网站首页那种卡片流），每张卡片显示
缩略图、时长徽章、文件名（两行）、分辨率·体积·时长、以及标签 chips。

左栏下半部分是**筛选**：年份 / 分辨率 / 时长 / 封面都是**胶囊按钮**
（不是下拉按钮），选中的高亮，一眼能看出当前选了什么；
一排排不下会自动换行；只有真的改了条件，标题右边才出现「N 项」和「重置」。

**筛选区是可折叠的表单，而且小窗下不会显示不全**：

- 点 `▾ 筛选` 收起 / 展开；
- 最多占左栏高度的 55%，剩下的留给标签列表（标签是主导航，不能被挤没）；
- **装不下的内容会滚动**，不会被切掉 —— 窗口一矮、或者年份选项一多，
  表单就在自己的滚动区里滚，滚动条只在真的需要时才出现；
- 表单的高度跟着内容走：年份多几个，筛选区就高一点，而不是永远停在初始高度。

（窗口多小都不会「显示不全」这件事现在有两个测试盯着：
一个断言装不下时必须能滚，一个断言窗口够高时不该出现滚动条。）

**右侧详情面板可以一键收起 / 展开**：按钮就在面板右上角，是一个**粉色圆角胶囊**
（展开时浅粉底 `»`，收起时实心玫红 `«`），一眼能看见。
收起后整条窄边染成粉色圆角块（34px，四角 10px 倒角），按钮仍在原位 ——
不用像拖分隔条那样「拖没了就找不回来」。

- 也可用 `⋯` 菜单里的「显示详情面板」勾选切换；
- 展开时面板有最小宽度，拖分隔条拖不成一条缝；
- 反过来把窄条往左拖开，会自动展开。

### 标签页怎么用

| 操作 | 效果 |
|---|---|
| 左键点左侧标签 | **在新标签页打开**该标签；同一个标签重复点只会切过去，不会开两个 |
| `Ctrl` + 点标签 | 把标签加到**当前页**的筛选里（多个标签 = 同时具备），不开新页 |
| 点「全部视频」 | 回到固定的主页（主页不能关闭） |
| 点标签上的 `✕` | 关闭这一页（主页没有 `✕`，因为它关不掉） |
| 中键点标签 | 同上，关闭这一页（浏览器的老习惯） |
| 拖动标签 | 换位置。拖过之后「标签」和「下面的内容」仍然绑在一起 |
| 标签页右键 | 关闭 / 关闭其他 / 关闭右侧 / 重命名标签 / 删除标签 / 刷新本页 |
| `Ctrl+T` | 打开主页；`Ctrl+W` 关闭当前页；`Ctrl+Tab` 切换页 |

> 那个 `✕` 是自己画的，不是 Qt 的 `QTabBar::close-button`。后者在自定义样式表下
> **不画任何东西** —— 按钮对象在、位置对、点得着（能关掉页），但屏幕上一片空白，
> 于是看起来就像「这一页没有关闭按钮」。所以样式表里没有动它，而是换成
> 自己画的 `QToolButton#tabClose`，颜色和悬停反馈都跟着主题走。
> `tests/test_gui.py::TestTabCloseButton` 里有一个**抓像素**的测试专门盯这件事：
> 按钮那 18×18 的方格里必须真的出现字形像素。
>
> 它的**上下位置**也踩过一个坑：Qt 把标签上的按钮居中在**原始标签矩形**里，
> 而标签文字是按样式表的 `margin + padding` 居中的。只要标签自己留
> `margin-top`（"浮"在标签条上、上面空一道），两者就差出半个空隙 ——
> 表现就是 `✕` 比文字高 4px。现在顶部那道空隙改由标签条容器留
> （`tabs.py` 里 `tab_row` 的上边距），两边按同一套盒子模型居中，
> 墨迹中心严格落在同一行（`test_close_button_is_vertically_aligned_with_the_title`
> 量的就是这两团墨迹的中心，误差 ≤ 1px）。

**每个标签页各有一份独立的查询状态**：筛选、排序、搜索词、滚动位置互不干扰。
主页看全库，标签页看某个标签，两个页可以同时开着、各看各的。

### 快捷键

`Ctrl+F` 搜索（浮动搜索条，`Esc` 收起）· `Ctrl+R` 扫描 · `F5` 刷新当前页 ·
`Ctrl+T` 主页 · `Ctrl+W` 关闭当前页 · `Ctrl+Tab` 切换 · `Ctrl+Z` 撤销标签操作 · `Ctrl+Q` 退出

### 刷新

`F5`，或者 `⋯` 菜单里的「刷新当前页（F5）」。刷新会**保住你的浏览进度**：

- 已经翻出来的条数不会被退回第一页；
- 滚动位置原样保留，不会被弹回顶部；
- 选中项保留（即使它在后面几页）；
- 顺带刷新左侧标签计数。

**筛选 / 搜索 / 排序**是另一回事：结果集整个变了，这时会回到顶部看新结果。
这两类行为的区别写在 `VideoPage.refresh()` 的 `keep_view` 参数上
（默认跟随 `keep_selection`）。

> **别跟 `⟳` 搞混**，这是两个不同量级的动作：
>
> | | 快捷键 | 干什么 | 碰硬盘吗 |
> |---|---|---|---|
> | 刷新当前页 | `F5` | 重跑一次查询，重新读索引库 | 不碰 |
> | 重新扫描文件夹 | `Ctrl+R` / `⟳` | 真的去遍历目录、增量入库、给新文件跑 ffprobe | 碰 |
>
> 新拷进来的视频要按 `⟳` 才会出现；`F5` 按一百次也扫不出新文件。
> 扫描在后台线程里跑，完成后自动通知所有页面和左侧标签计数，界面不卡。

### 其它

- **缩略图**：ffmpeg 抽帧并缓存在 `var\thumbs\`，只有**当前可见**的卡片才去抽帧，
  滚动停下 120ms 才批量发请求，所以快速滚动不会堆一堆没用的任务。
- **文件读不到时**：卡片会显示「文件不可用（磁盘未接或已移走）」而不是傻等缩略图 ——
  索引库指向的硬盘拔掉后，一眼就能看出问题在哪。
- **打标签**：右侧详情面板输入回车，或选中后右键「打标签…」。两种方式都支持
  一次输入多个标签（逗号 / 中文逗号 / 顿号都认），并会补全库里已有的标签；
  「移除标签…」和标签页右键的「重命名标签…」用的是同一个输入框。
- 界面里的写操作只改索引库，**不会删改任何视频文件**。

## 打包成 Windows 程序

```powershell
py tools\build.py
```

跑完在 `dist\视频管理器\` 里得到（约 95 MB，PyQt5 占大头）：

| 文件 | 说明 |
|---|---|
| `视频库管理.exe` | 图形界面，双击即用 |
| `vm.exe` | 命令行（scan / rename / dupes / tag / report） |
| `vm_config.toml` | 配置，打包时从项目目录带过来 |
| `var\` | 索引库、标签备份、改名日志（带一份） |
| `使用说明.txt` | 给使用者看的说明，随包生成 |

> 命令行版不是附赠品：改名、查重、生成报表这些批量动作本来就在命令行里更顺手，
> 图形界面里没做。只打界面等于把一半功能删了，所以两个都打。

**不包含 ffmpeg** —— 几十 MB，而且它有自己的许可证。程序会去
exe 同目录、`bin\`、`tools\`、以及 `PATH` 里找；找不到只是没有缩略图，
其余功能照常（`vm.exe roots` 会告诉你它找到的是哪个）。

### 为什么要把 var\ 带一份过去

配置里的相对路径是**相对 exe 所在目录**解析的。带过去之后，打包版一打开
就是熟悉的索引和标签，而不是一个空库。代价是它和源码目录那份从此各自独立
—— **用哪份就固定用哪份**。想合并：一边「⋯ 菜单 → 导出标签备份」，
另一边「从备份导入」。

### 打包踩过的三个坑

- **`__file__` 在打包后指向解包目录**。所以 `core/config.py` 的 `project_dir()`
  必须判断 `sys.frozen`，冻结后取 **exe 所在目录**。不判断的话配置文件读不到、
  索引库和标签备份会写进临时目录（单文件模式下每次启动还是个新目录，退出就没），
  表现就是「每次打开都像第一次，索引和标签全空」。
  `tests/test_vm.py::TestPackagedPaths` 盯着这件事。
- **`--db` 的相对路径**：CLI 以前把原始参数直接交给 `open_db`，于是
  `--db var\x.db` 在**当前工作目录**建库，而标签备份按程序目录算 —— 两个不同的
  文件。打包之后更容易踩（快捷方式的工作目录不是程序目录）。现在统一走
  `cfg.db_path`（rebind 时已经解析过），`TestCliDbPath` 是它的回归测试。
- **构建工具不装进系统 Python**：这台机器上 pip 写不了工作区以外的目录
  （系统 site-packages 和 `%APPDATA%\Python` 都被拒），所以 PyInstaller 装在
  `D:\ds_workplace\_build_tools`，`tools\build.py` 会自动找到它并用 `PYTHONPATH`
  指过去 —— 既不动系统 Python，也不往项目里塞东西。

## 命令行快速开始

```powershell
cd D:\ds_workplace\video_manager

py vm.py roots                                  # 看配置、ffmpeg 路径、根目录是否存在
py vm.py scan                                   # 扫描入库 + 元数据探测（增量，第二次秒过）
py vm.py stats                                  # 整体统计
```

### 标签的三个设计决定

**1. 规范化存储。** `tags.key` 是唯一键（去空白 + 折叠大小写），`tags.name` 是显示名。
所以 `1080P` 和 `1080p` 是同一个标签，不会分裂成两个。

**2. 用关系表，不往字段里塞逗号。** `file_tags(file_id, tag_id)` 是多对多关系表，
所以 `tag rename` 是 **一条 UPDATE**，而不是重写每一条记录；
`tag rename 新名` 遇到已存在的标签会自动合并，不产生重复。

**3. 索引库从此不再是可以随便删的缓存。**
之前 `var\video_index.db` 删了重扫就能重建；**标签是你手工敲进去的、磁盘上推导不出来的数据**。
所以每次写标签都会自动导出 `var\tags_backup.csv`（带 BOM），并且可以在
`tag journal` 里看到每一步、用 `tag undo` 回滚。请把这两个文件也纳入你的备份范围。

### 文件改名/移动后标签不会丢

扫描是靠路径认文件的，所以文件改名后会出现「旧记录标记消失 + 新记录」，
标签原本会挂空。`relink` 用 **文件大小 + 修改时间**把标签接回新文件：

- 同盘改名/移动会完整保留修改时间 → 精确匹配，可靠；
- 跨盘拷贝可能丢亚秒精度 → 退回到整秒匹配；
- **如果同时有多个文件的大小和修改时间都一样（有歧义），程序会拒绝迁移而不是猜**，
  这时会报告"无法唯一配对"，需要手工处理。

`vm scan` 结束时会自动跑一次 relink，所以正常整理文件后只要扫一遍就行。

### 精简规则（按顺序）

| 步骤 | 做什么 | 例子 |
|---|---|---|
| ⓪ | 去掉与所在目录同名的冗余前缀 | `ScreenRecorder\Screenrecorder-2026-08-26-11-07-50-589` → `2026-08-26-11-07-50-589` |
| ⓪ | 去掉爬虫前缀（纯 ASCII+下划线，且后面还有中文） | `Ezma_python1_pachong爬神奇的website2黑丝00后…` → `爬神奇的website2黑丝00后…` |
| ① | 去掉站点尾巴 | `… - 黄色仓库-hsck.net` |
| ② | 去掉营销词 | `详情介绍` / `在线观看` / `迅雷下载` / `高清资源` / `ALIBB影视` … |
| ③ | 收敛多余分隔符 | `A -  B` → `A-B` |
| ④ | 去重复标题 | `COS淫色胡桃-甜心-COS淫色胡桃-甜心-COS淫色胡桃-甜心` → `COS淫色胡桃-甜心` |
| ⑤ | 仍超长才从头截断 | `Hidori Rose with Enafox Chocola and Vanilla` → `Hidori Rose with Enafox Chocol` |

实测在 HSCK 的 49 个超长文件名上：**46 个纯靠 ⓪–④ 就够了，一个字的有用信息都没丢**，
只有 3 个需要截断。

第 ④ 步要认得出两种真实形态，都写进测试了：

- `标题-标题`（两份，第二份被尾巴截断）
- `A-B-A-B-A-B-黄`（三份完整重复 + 一个多余尾巴，多余的部分保留不擅自丢）

### 安全措施

这是本项目**唯一会改动视频文件的功能**，所以规矩最严：

1. **默认只试运行**，必须显式加 `--apply`；
2. 每一步写日志到 `var\rename_journal.csv`，`rename --undo` 原样还原（还原后日志条目会被移除，避免重复回滚）；
3. **改名后直接就地更新索引库的 path / name / rel**，而不是让扫描去重认 ——
   文件 ID 不变，所以**标签、哈希、探测结果全都原封不动跟着走**；
4. 目标名冲突时自动加 `-2`、`-3` 后缀，绝不覆盖已存在的文件；
5. 计划做好之后文件又变了大小（还在录制/拷贝），**跳过不动**；
6. 只重命名，不改扩展名、不移动目录。

> 实测：49 个文件改名后重新扫描，结果是「未变 59、已消失 0、新增 0」，
> 标签 `1080p`(14) / `胡桃系列`(4) 数量完全不变。

## 查重是怎么做的

三级递进，上一级不重复就不会进入下一级，所以不会真的把整盘读完：

1. **文件大小**：一条 SQL 按 size 分组，`HAVING COUNT(*) > 1`，秒级筛出可疑集合；
2. **首尾各 1 MiB**（`quick_hash`）：把「大小相同但内容不同」的排掉；
3. **全文哈希**（`full_hash`）：确认是否真重复。

哈希值会写回索引，下次查重直接复用；只有大小或修改时间变了才会重算。
哈希算法默认 `blake2b`（16 字节摘要，比 md5 快且更抗碰撞），
需要和旧脚本 `copy_files.py` 对得上时可以改成 `md5`。

每组重复文件会给出一个「★保留」建议，判定顺序是：
文件名不像副本 → 目录层级浅 → 路径短 → 时间早。

> 目前 HSCK 目录实测 0 组重复（都是不同成片，符合预期）。
> 查重引擎的正确性由 `tests/test_vm.py` 覆盖：既能找出真重复，也不会把
> 「大小相同、内容不同」误判成重复。

## 实现上的几个要点

- **增量扫描**：比对「大小 + 修改时间」，没变的记录只刷新 `last_seen`，
  所以第二次扫描 59 个文件几乎瞬间完成；文件消失会标 `missing=1` 而不是删记录。
- **改过的文件自动作废缓存**：内容一变，旧的探测结果和哈希全部清空重算。
- **长路径**：绝对路径长度 ≥ 240 时自动加 `\\?\` 前缀，入库时再剥掉，路径始终可读。
- **中文安全**：控制台强制 UTF-8；CSV 带 BOM；HTML 里中文和长文件名用 `file:///` 链接。
- **管道友好**：输出到终端时进度原地刷新，重定向到文件时改成按时间节流打印。
- **标签写操作可回滚**：每一次打/摘标签都记一条日志，`tag undo` 逆序回滚；
  删除标签时会把受影响的文件 ID 一起存进日志，所以连「删标签」都能撤销。
- **网格用 delegate 画，不是给每格塞控件**：Qt 只会为可见的卡片调 `paint()`，
  几万个文件也不会因为创建几万个控件而卡死。
- **换库时标签备份跟着挪**：`--db` 指定另一个索引库时，备份/日志会写到那个库旁边，
  不会覆盖主库的标签备份。
- **后台线程各自开自己的数据库连接**：SQLite 连接不能跨线程用
  （`sqlite3.ProgrammingError: SQLite objects created in a thread can only be
  used in that same thread`）。所以 `⟳` 扫描不是把界面线程的连接带进工作线程，
  而是走 `Engine.scan_in_own_connection()`，在工作线程里自己 `open_db()` +
  `finally: close()`。**这个坑让 `⟳` 从做出来那天起就是坏的**：异常抛在后台线程里，
  界面只是「按了没反应」，看起来像按钮没接线，其实连了。
  现在有从界面真点一次 `⟳` 的回归测试盯着（`TestScanFromGui`）。

> 函数本身照跑。
>
> 教训有两条：**槽里的异常会直接杀进程**（写错一个 API 名就是闪退，不是报错），
> 以及**替身替换得越靠外越安全**，替掉待测函数本身等于没测。

> **跑测试必须让 Qt 找得到字体。** offscreen 平台不会自己去认系统字体，
> 不指定 `QT_QPA_FONTDIR` 的话 Qt 只会刷一句
> `QFontDatabase: Cannot find font directory`，然后**任何文字都画不出来**：
> 标签文字、按钮字形、提示语统统是空白，而所有不看像素的断言照样全绿。
> 这个坑是「标签上那个 `✕` 到底画没画出来」才暴露的 —— 测试跑在没有字体的
> 环境里，抓像素只能抓到 0。

> **这里有个明确的测试盲区**：无边框窗口的「拖动、缩放、Aero Snap 手感」
> 是窗口管理器行为，离屏环境**完全测不了**。单测只覆盖了几何计算
> （边缘判定、位移、最小尺寸钳制）和信号接线；真实手感必须人眼看。
> 为此提供了 `--native-frame` 逃生通道。
>
> **窗口圆角同理，还多一层**：offscreen 平台根本没有 DWM，圆角是系统画的，
> 离屏渲染出来的永远是方角。单测只能覆盖「什么时候该要圆角」，
> 「刀口切得对不对、弧线糙不糙」必须**在真机上截屏看**：
> 摆一个窗口，用 `QScreen.grabWindow(0)` 抓整屏，再采样四个角 ——
> 窗口模式下角上是窗口外的东西（说明被切了），最大化时角上必须是窗口自己的内容
> （说明没切）。这套真机检查做过，窗口模式 / 最大化 / 还原三种状态都对。

> 界面测试与「离屏渲染预览图」是互补的：单测能抓信号连错、状态不对；
> 但**画面到底显示了什么，只有把图渲染出来看才知道**。
> 这次重构里，「标签条切了、状态全对，但网格还显示第一页」这个 bug
> 单测全绿、预览图一眼看出 —— 因为 `QTabBar` 和 `QStackedWidget` 忘了连线。
> 同类问题还有两个：状态栏计数一直空着（`addTab` 触发 `currentChanged` 时
> 页面还没登记进列表）、详情面板永远停在「正在生成缩略图」（缩略图回调只通知了网格）。
